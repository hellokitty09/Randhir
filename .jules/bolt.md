## 2024-03-24 - Unnecessary scroll event handler
**Learning:** The project implements a hybrid animation approach: modern pages (index.html, destinations.html, about.html) use inline `IntersectionObserver` scripts, while `contact.html` uses an external `script.js`. The `script.js` file contains a scroll event listener that calls `getBoundingClientRect()` on every scroll event to trigger animations for `.gallery-item` elements. However, none of the HTML pages in this repository actually contain elements with the class `.gallery-item`. This means the application is executing layout-heavy calculations on every scroll event for elements that don't exist. Furthermore, even if the elements did exist, a scroll event listener that triggers layout calculations without throttling or `requestAnimationFrame` is a well-known performance anti-pattern that can cause scroll jank.
**Action:** When auditing legacy scripts in a project that is transitioning to modern APIs like `IntersectionObserver`, verify that the selectors in legacy scroll handlers actually match elements in the DOM. If they do, refactor the handler to use `IntersectionObserver` or, at a minimum, throttle it using `requestAnimationFrame`. If they don't, remove the dead code to eliminate unnecessary processing.
