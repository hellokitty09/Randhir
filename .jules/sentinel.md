## 2024-06-22 - [Add Content Security Policy (CSP) headers]
**Vulnerability:** [Missing protection against Cross-Site Scripting (XSS) via lack of Content-Security-Policy (CSP) headers in a static website serving multiple HTML files, allowing arbitrary script/style injection.]
**Learning:** [The static site utilizes external fonts and styles via CDNs (`cdnjs.cloudflare.com`, `fonts.googleapis.com`, `fonts.gstatic.com`) and external images via `images.unsplash.com`. Furthermore, the HTML structure relies heavily on inline styles and scripts (like ` IntersectionObserver` in `script` tags). Therefore, `unsafe-inline` was necessary for script/style. The CSP needed to balance security (blocking arbitrary external sources) with functionality (allowing these specific external CDNs and inline functionality).]
**Prevention:** [Implement a robust `Content-Security-Policy` meta tag or HTTP header on all pages, defining specific allowed sources for scripts, styles, fonts, images, and connections (`script-src`, `style-src`, `font-src`, `img-src`, `connect-src`). Consistently apply this policy across all static HTML files, ensuring to explicitly whitelist required CDNs and evaluate if `unsafe-inline` can be refactored into external files in future iterations to further tighten security.]
